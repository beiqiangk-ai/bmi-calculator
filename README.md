# BMI 健康计算器

一个从命令行版本迭代到网页版的 BMI 计算工具,记录了我从零开始学习 Python,并用 AI 工具辅助完成网页化的完整过程。

## 项目背景

作为计算机应用技术专业学生,我在重新巩固编程基础时,选择用一个小而完整的项目来练手——BMI 计算器。项目从最基础的命令行程序开始,逐步迭代加入健康状态判断、循环交互、错误处理,最后用 AI 工具(Claude)辅助完成了网页版。

## 版本迭代过程

### V1 —— 基础计算
- 用户输入身高、体重
- 计算并输出 BMI 数值
- 踩坑记录:一开始把赋值符号 `=` 误写成减号 `-`,导致 `NameError`,通过读报错信息定位并修复

### V2 —— 加入健康状态判断
- 使用 `if / elif / else` 判断 BMI 属于偏瘦 / 正常 / 偏胖 / 肥胖
- 用 `%.2f` 格式化输出,保留两位小数

### V3 —— 循环 + 函数封装 + 错误处理
- 用 `while` 循环支持连续计算多个人的 BMI,输入"退出"结束
- 用 `def` 把计算逻辑和状态判断逻辑分别封装成函数
- 用 `try / except` 捕获非法输入(比如输入了非数字),避免程序直接崩溃
- 踩坑记录:把身高从"米"改成"厘米"输入时,函数内部计算时不小心用错了变量名(该用换算后的 `height_m`,误用了未定义的 `height`),导致算出的 BMI 始终是 0.00。通过读报错信息、检查变量名一致性定位并修复

### 网页版 —— AI 协作完成
在命令行版本跑通后,我想把它做成更多人能直接打开使用的网页工具。这一步我用 AI 工具(Claude)辅助生成了 HTML + CSS + JS 的前端代码框架,自己负责:
- 理解生成代码的结构和逻辑
- 实际测试功能,发现问题
- 提出优化需求,与 AI 反复迭代

**测试中发现的一个真实问题**:命令行版本要求身高按"米"输入(如 1.70),我自己测试时不小心输成了 170(以为是厘米),导致计算结果完全错误。我意识到这是一个容易踩坑的设计,于是把网页版的输入方式改成了更符合日常习惯的"厘米"输入,并加入了输入校验——如果用户没输入或输入了无效数值,会提示重新输入,而不是直接报错或算出错误结果。

## 技术栈

- Python(命令行版本):变量、条件判断、循环、函数、异常处理
- HTML + CSS + JavaScript(网页版):表单交互、DOM 操作、条件渲染
- Git / GitHub:版本管理,记录 V1 → V2 → V3 的完整迭代过程

## 我在这个项目中学到的

- 从"能跑起来"到"用户体验合理"之间,还有很多需要主动发现和打磨的细节
- 和 AI 工具协作时,AI 负责快速生成代码框架,我负责理解、测试、提需求、判断对错——这个分工让我能用有限的基础知识做出一个相对完整的作品
- 报错信息不是"失败通知",而是排查问题的线索,养成了先读报错、再定位问题的习惯
- 变量命名要保持前后一致,哪怕只是一个字母之差(如 height 和 height_m),也会导致程序运行结果完全错误却不一定报错
